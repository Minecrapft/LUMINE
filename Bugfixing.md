## BUG-001 · Upload UI completely missing from Datasets tab

**Severity:** Critical  
**Status:** FIXED (see fix below)

**Description:**  
The Datasets tab has an Annotate / Export CSV / Delete button per dataset row, but NO button to
upload photos. The upload panel HTML (`#upload-panel`) and its JavaScript were written but the
trigger was never wired to the table rows. As a result, it is impossible to add images to a dataset
from the ML Studio without using the raw API directly.

**Root cause:**  
The upload panel was removed when the template was condensed. The hidden `#upload-ds-id` input
is never populated, and no "Upload Photos" button exists in the dataset table.

**Fix:** Add an "Upload" button to each dataset row. Clicking it populates `#upload-ds-id` and
shows the upload panel. Re-added the upload panel card below the dataset table.

## BUG-002 · Only one file at a time — impossible for 700 images

**Severity:** Critical  
**Status:** FIXED (see fix below)

**Description:**  
The file `<input>` on the upload panel only accepts one file at a time (no `multiple` attribute was
effective for the server loop). Selecting 700 images one at a time is unusable.

The server-side `POST /api/datasets/<id>/samples` also only processes a single `file` field per
request. You would need 700 separate requests.

**Root cause:**  
- Frontend: `<input type="file">` needs `multiple` attribute and the JS loop must send them in
  parallel (or batched concurrently).
- Backend: No bulk endpoint; each call handles one file.

**Fix:**  
- Added `multiple` to the file input.
- JS now uploads all selected files concurrently in configurable batches of 5.
- Added a new `POST /api/datasets/<id>/samples/bulk` endpoint that accepts up to 50 files per
  multipart request, processes them in a loop, and returns a summary.
- Added a "Import folder" button via `webkitdirectory` attribute on a second input (Chrome/Edge/FF only).

## BUG-003 · Export CSV silently fails when dataset has no labels

**Severity:** Medium  
**Status:** FIXED

**Description:**  
When a dataset has samples but no pad labels, `GET /api/datasets/<id>/export/csv` returns
`HTTP 404` with a JSON body `{"error": "No labelled data in this dataset"}`.

The JS calls `window.location.href = '/api/datasets/.../export/csv'` — so the user sees the browser
navigate to a page that shows raw JSON `{"error": "..."}` instead of an actionable error message
in the UI. No toast/alert is shown.

**Fix:**  
Replaced the bare `window.location.href` navigation with a `fetch` call that checks the
response Content-Type. If JSON (error), show an in-page alert. If `text/csv`, trigger download
programmatically via a Blob URL.

## BUG-004 · ZIP import / CSV label import not available

**Severity:** High  
**Status:** FIXED (see fix below)

**Description:**  
With 700 images to upload and label, there is no way to:
- Upload a whole folder at once as a ZIP archive.
- Import a pre-made CSV of labels (e.g. auto-generated by `scripts/make_synthetic.py`).

Users with large datasets are blocked from using the ML pipeline.

**Fix:**  
- Added `POST /api/datasets/<id>/import/zip` — accepts a `.zip` file containing images (and
  optionally a `labels.csv`). Images are extracted, re-encoded, and registered. If `labels.csv`
  is present, labels are parsed and saved automatically.
- Added `POST /api/datasets/<id>/import/labels_csv` — accepts a CSV with columns
  `sample_id, marker, pad_index, true_level, label_source, pad_color` and upserts labels.
- Added corresponding UI: "Import ZIP" and "Import Labels CSV" buttons in the Datasets tab with
  progress indication.

## BUG-005 · Upload panel dataset selector never set

**Severity:** Medium (blocked by BUG-001)  
**Status:** FIXED (part of BUG-001 fix)

**Description:**  
The `<input type="hidden" id="upload-ds-id">` was never populated by any button click.
When the upload form was submitted, `dsId` would always be an empty string, causing the upload
to fail silently (the `fetch` call would POST to `/api/datasets//samples` — a 404).

**Fix:**  
Each dataset row now has an "Upload" button that sets `#upload-ds-id` and shows the upload panel
before the user selects files.

## BUG-007 · Training dataset checkboxes not refreshed after upload

**Severity:** Low  
**Status:** FIXED

**Description:**  
After uploading new samples the page does not reload, so the Training tab still shows the old
sample count in the dataset checkboxes. The user may start training before the samples are fully
registered.

**Fix:**  
After bulk upload completes, automatically refresh the sample counts in both the dataset table
and the training checkboxes via a `GET /api/datasets` call, without a full page reload.

## BUG-008 · No progress feedback during large bulk upload

**Severity:** Medium  
**Status:** FIXED (part of BUG-002 fix)

**Description:**  
When uploading many files, there is no per-file feedback — the UI freezes. The user cannot tell
how many files have been processed.

**Fix:**

`N of 700 uploaded (M failed)`. Failures are listed below the bar with filename and error reason.

## How to Upload 700 Images

**Option A — Folder select (easiest in Chrome/Edge/Firefox):**
1. ML Studio → Datasets tab → click **Upload Photos** on your dataset row
2. In the upload panel, click **Select Folder** — pick the folder with your 700 images
3. The counter shows how many JPEG/PNG files were found
4. Click **Upload Selected Files** — files upload in batches of 5 with a live progress bar

**Option B — ZIP archive (best for very large batches):**
1. Zip your images: `Compress-Archive -Path images\* -DestinationPath dataset.zip`
2. Optionally include a `labels.csv` in the ZIP root with columns `filename, marker, pad_index, true_level`
3. ML Studio → Datasets → **Upload Photos** → switch to **ZIP Archive** tab → upload the ZIP
4. Images (and labels if included) are imported in one operation

**Option C — Drag and drop:**
- Drag multiple files from Explorer onto the drop zone in the Photos tab

**Option D — Import Labels CSV (for pre-labelled data):**
- After uploading images, use **Import Labels CSV** tab with columns:
  `sample_id, marker, pad_index, true_level` (get sample IDs from Export CSV first)
